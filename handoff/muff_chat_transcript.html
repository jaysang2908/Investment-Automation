SESSION 1 — GOOGLE TRENDS DEEP DIVE
Justin

not necessarily just specifically for the ticker symbol. A lot of the narrative could be sector specific… How do we ensure we capture this?

Great point. We solve this with a sector-level keyword layer in Google Trends. Each narrative theme (e.g. "AI / Machine Learning") maps to 1–2 sector search terms ("AI stocks", "artificial intelligence investing") that run alongside the ticker in the same pytrends query.

Justin

sorry what the hell do those numbers mean? like 100/100 and 38-46 are they units of something

Claude

Good question — Google Trends doesn't give you actual search volume numbers. It gives you a relative 0–100 index:

  • 100 = the peak day in the queried window (not 100% of all searches, just the busiest day for that term)
  • 50 = half as much interest as that peak day
  • 0 = basically no searches

The ratio we compute (e.g. 2.0×) is: average of last 7 days ÷ average of the prior period. So 2.0× means the last 7 days are getting double the search interest compared to the prior baseline. That's the surge signal.

Critically — all terms in the same query share the same 0–100 scale, so they're directly comparable to each other.

Justin

ah cool that makes sense, thanks, yes please add custom search terms functionality. How prescriptive is this btw? like is it the EXACT words i put in the search term or will it also show data/analyse relevant stuff similar to that search query

Claude

Phrase-match, not exact. "HBM memory" will also capture "HBM memory chips", "HBM memory bandwidth", etc. It's not case-sensitive either.

It won't go fully semantic (it won't connect "HBM memory" to "DRAM" without you specifying both). So for best signal quality, use 2–3 word compound terms rather than single words — "AI" is too broad (captures everything), "AI inference chips" is specific enough to mean something.

Custom terms will merge into the single pytrends query alongside the ticker and auto-selected theme keyword. Max 5 slots total: [ticker, theme_kw, custom_1, custom_2, custom_3].
